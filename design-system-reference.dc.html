Vertical rhythm

Vertical space is a ladder, not a set of guesses: the gap between two things says how related they are. Every value on it comes off the 4px base.

One step per relationship Inside a component 8px, between a label and its value 4px, between components 16px, between a figure and its caption 16px, between rows of a gallery or list of cards 64px. If two gaps in the same view are within 4px of each other, one of them is wrong.
Space belongs to the container Use gap on a flex or grid parent rather than margins on children, so inserting, deleting or reordering an item cannot change the spacing.
Never stretch a caption away from what it describes A caption sits 16px under its subject. Do not use height:100% with margin-top:auto to bottom-align captions across a grid row: a short caption drifts away from its own image and lands hard against the next row. Align grid items to the top and let the row gap do the separating.
Row gap exceeds the tallest text block In a grid of captioned items, the row gap must be larger than the tallest caption, or two captions read as one paragraph. 64px against a three-line caption.
An icon beside text sits on the first line Align the row to the top and give the icon a box exactly one line tall, centred within it. One line of text then reads as centred; two or more keep the icon at the top instead of floating to the middle of the paragraph. Never align-items:center on a row whose text can wrap.
One rhythm per page A page uses one set of steps throughout. A section that needs different spacing is a different component, not a different scale.

Accordion

For reference detail a user consults rather than reads. Scope definitions, error codes, bank-specific caveats. Never for steps in a task.

Why does authorisation expire after 90 days?
Under the regulation, account access consent lapses after 90 days unless the user re-authenticates with their bank. The console shows the expiry date on every consent and sends a webhook seven days before it lands.
Which scopes does a single-payment consent need?
A single domestic payment needs only the payment scope. Requesting account scopes alongside it lengthens the bank’s own consent screen and measurably lowers completion.
What happens if the bank is unavailable?
The journey stops at a status screen naming the institution, and offers the user a route back to pick a different bank rather than a dead end.
Notes Built on native <details> and <summary>, so keyboard operation, in-page find and print expansion come free. No ARIA and no state to manage. Panels open independently; nothing closes as a side effect of opening something else. Summaries are questions or nouns, never “More”.

Outcome mark

The single symbol that opens any end-of-journey screen: payment initiated, mandate active, bank connected, declined, timed out. One shape, one size, one tinted disc, so a user who has seen one outcome recognises the next without reading it. A bare glyph is never used for an outcome, and no outcome screen invents its own illustration.

Variants
Success#DCFCE7 / #08611F
Failure#FEF2F2 / #C10007
Waiting#FEFCE8 / #973C00
Rules
60px disc, 24px glyph, always The disc carries the meaning; scaling the glyph instead breaks recognition between screens.
Never colour alone The heading states the outcome in words directly under the mark, and says whether money moved or data was shared.
One mark per screen An outcome screen shows one, at the top, centred, above the heading. No mark on a screen the user can still act on.
Three variants, no more Success, failure, waiting. A deliberate cancellation uses failure with plain wording, not a fourth colour.

Inline field warning

A warning attached to the field it concerns, not to the top of the form. Used where the risk is specific to one input. The TAN warning on a bank login is the case that justified building it, because a phishing page asks for exactly that and a generic banner at the top would be scrolled past.

Modal and dialog

Reserved for a decision that cannot be deferred. Confirming something destructive, or a short task that would lose context on its own page.

Standards

Writing and voice

The product is infrastructure for people handling other people’s money. It speaks plainly, says what happened, and never sells inside the interface.

Write this Barclays did not return a response. Try again, or pick another bank. Your closure request is being processed. Your account closes on 3 September 2026. 642,000 of 1,000,000 API calls used. Resets 1 September. Rename…
Not this Oops! Something went wrong. Your request is in the queue. We’ll be in touch soon! 64% used Rename…
Rules Sentence case everywhere except the wordmark. Second person for the user, first person plural only when Yapily is genuinely acting. No exclamation marks, no apologies that carry no information, no jargon the user has not already met in their own integration. Errors have three parts: what happened, why, what to do next. Buttons are verbs naming their object, “Delete application”, not “Confirm”. Dates are written out (3 September 2026) to avoid the transatlantic ambiguity of 03/09. Curly quotation marks, a real ellipsis character, and non-breaking spaces in units and shortcuts: 10 MB, 412 ms, ⌘ + K.

Keyboard and focus

Every flow is operable without a pointer. Focus is always visible, always somewhere sensible, and always returned to where the user left it.

ArrowsMove within a composite: tabs, button group, menu, combobox list, table rows.

Error and edge cases

A component is not finished when the happy path works. These are the states every component is reviewed against before it ships.

StateWhat it must do
LoadingDelay the indicator 150–300ms so fast responses never flash, then hold it 300–500ms so it never blinks. Skeletons match the real layout and do not shift it on arrival.
EmptySay what will fill the space and offer the action that fills it. Never a blank panel.
SparseOne row must look deliberate, not broken. Fixed heights that assume ten rows are a bug.
Dense1,742 rows stay responsive: virtualised list, pagination stating the range and total.
Long contentBank names, user-generated app names and German institution names all fit. Wrap by default; truncate only identifiers, and never without the full value available.
ErrorName what happened, why, and the next step. Sits beside the thing it concerns, and focus moves to the first invalid field.
PermissionUnavailable actions stay visible and explain the missing role instead of disappearing.

Rules No dead ends: every state offers a next step, a recovery path, or a way back out. A screen a user can reach and not leave is a defect. Where success is near-certain, update optimistically and offer Undo. Where it is not, wait and report honestly.

Contribution and versioning

The system is maintained by the people who use it. Adding to it is a normal part of shipping a feature, with a defined route and a defined bar.

1 Use what existsMost new screens are existing components in a new arrangement. Reuse before proposing. 2 Build it locally firstA one-off lives in the feature until a second team needs it. Two uses is the threshold for promotion; one use is a pattern, not a component. 3 Promote with all its statesEntry requires the eight states, keyboard operation, an anatomy note, and an entry in this reference. Incomplete components are not accepted. 4 Deprecate loudly, remove quietlyA replaced component is marked deprecated with its successor named, and stays for one minor version before removal.

The three layers

Primitives are raw values and belong to no system. Semantic tokens name a job. Each system binds the semantic names to its own primitives, which is why one component set can serve a product console, a themed consent journey and a marketing site.

layer 1
Primitive

Hex values, the 4px step, the type ramp. Shared verbatim by all three systems.

layer 2
Semantic

Names a job, not a colour: --primary, --surface-brand, --radius-control.

layer 3
System binding

Yapily UI, Custard and Mark each resolve the semantic layer differently. Components never change.

components read layer 2 onlyCustard exposes 4 of layer 3 to customers
